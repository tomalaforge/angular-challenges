# Race condition

В этом задании мы столкнёмся с классической race condition в RxJS — «гонкой» между отложенным HTTP-запросом и открытием модального окна.

## 0. Запуск приложения

Перейди в папку задачи и выполни команду:

```bash
npm install
npm run serve:rxjs-race-condition
```

После запуска откроется приложение с одной кнопкой **Open Topic**. По нажатию на кнопку должно открыться модальное окно со списком тем (Politic, Culture, Nature и т.п.).

## 1. Посмотри, как работает код

Открой файлы:

- `src/app/app.component.ts` — корневой компонент с кнопкой и логикой открытия модалки.
- `src/app/topic.service.ts` — сервис, который «получает» темы с сервера.
- `src/app/topic-dialog.component.ts` — модалка, которая показывает список тем.
- `src/app/app.component.cy.ts` — Cypress-тест, который нужно починить.

В `TopicService` метод `fakeGetHttpTopic` возвращает `Observable<TopicType[]>` с задержкой 1 секунда (имитация медленной сети):

```ts
fakeGetHttpTopic = () =>
  timer(1000).pipe(map((): TopicType[] => ['Politic', 'Culture', 'Nature']));
```

В `AppComponent`:

```ts
ngOnInit(): void {
  this.topicService
    .fakeGetHttpTopic()
    .pipe(take(1))
    .subscribe((topics) => (this.topics = topics));
}

openTopicModal() {
  this.dialog.open(TopicModalComponent, {
    data: { topics: this.topics },
  });
}
```

То есть:

1. В `ngOnInit` мы подписываемся на получение тем.
2. Когда темы пришли, сохраняем их в `this.topics`.
3. По клику открываем модалку и передаём ей `this.topics`.

## 2. Запусти Cypress-тест

В отдельном терминале выполни:

```bash
npx nx component-test rxjs-race-condition
```

или в watch-режиме:

```bash
npx nx component-test rxjs-race-condition --watch
```

🚫 Тест падает. Cypress жалуется на то, что в модалке не три `<li>`, а ноль.

## 3. Пойми проблему

Пройди сценарий руками:

1. Открой приложение в браузере.
2. Сразу же (не дожидаясь загрузки) нажми **Open Topic**.

Что происходит:

- `ngOnInit` запустил запрос, но ответ ещё не пришёл (1 секунда задержка).
- `this.topics` всё ещё `[]`.
- Модалка открывается с пустым списком.

Это и есть race condition: открытие модалки «обгоняет» приход данных.

## 4. Почини приложение

Цель — к моменту открытия модалки темы уже должны быть загружены. При этом:

- Изменять `fakeGetHttpTopic` **нельзя** (он моделирует медленную сеть).
- Изменять Cypress-тест **нельзя** (он проверяет корректное поведение).

Возможные подходы:

1. Открывать модалку **только после** того, как пришли темы: вместо подписки в `ngOnInit` сразу вызывай `fakeGetHttpTopic()` в обработчике клика и открывай диалог в коллбэке `subscribe` (или в операторе типа `tap`).
2. Кэшировать результат: сохранять результат первого запроса и переиспользовать его при повторных открытиях модалки.
3. Использовать `shareReplay` / `cache` / `toSignal`, чтобы загрузка и отрисовка шли согласованно.

Подумай, какой вариант лучше подходит под существующую структуру.

## 5. Проверь решение

1. Перезапусти Cypress-тест — теперь он должен проходить:

   ```bash
   npx nx component-test rxjs-race-condition
   ```

2. Проверь поведение руками:
   - Открой приложение.
   - Сразу нажми **Open Topic** — в модалке должны быть все три темы (Politic, Culture, Nature).
   - Закрой модалку, открой ещё раз — темы должны появляться мгновенно (без повторной задержки), если ты выбрал подход с кэшированием.

## Ограничения

- Нельзя менять `TopicService.fakeGetHttpTopic` — задержка должна остаться как имитация медленной сети.
- Нельзя менять Cypress-тест в `app.component.cy.ts`.
