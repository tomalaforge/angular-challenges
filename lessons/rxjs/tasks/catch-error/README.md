# catchError

В этом задании мы научимся правильно обрабатывать ошибки в RxJS-потоках с помощью оператора `catchError`.

## 0. Запуск приложения

Перейди в папку задачи и выполни команду:

```bash
npm install
npm run serve:rxjs-catch-error
```

После запуска откроется приложение — форма с полем ввода и кнопкой **Получить**. По нажатию на кнопку приложение отправляет запрос к бесплатному API https://jsonplaceholder.typicode.com/ и показывает ответ на экране.

## 1. Посмотри, как работает приложение

В поле ввода можно ввести одну из строк:

- `posts`
- `comments`
- `albums`
- `photos`
- `todos`
- `users`

Нажми кнопку **Получить** — внизу появится JSON-ответ от API.

Посмотри на код в `src/app/app.component.ts`. Видно, что в `ngOnInit` создаётся подписка на поток `submit$`, и каждое нажатие кнопки порождает HTTP-запрос через `concatMap`.

## 2. Воспроизведи баг

Введи в поле что-нибудь некорректное — например, `foo` или просто случайный набор символов — и нажми **Получить**. В ответе придёт ошибка `404 Not Found`. Это ожидаемо.

А теперь попробуй снова ввести корректное значение (например, `posts`) и нажать **Получить**.

🚫 Ничего не происходит. Запрос не отправляется, поле ответа не обновляется.

## 3. Найди причину

Открой `src/app/app.component.ts` и посмотри на `ngOnInit`:

```ts
this.submit$
  .pipe(
    map(() => this.input),
    concatMap((value) =>
      this.http.get(`https://jsonplaceholder.typicode.com/${value}/1`),
    ),
    takeUntilDestroyed(this.destroyRef),
  )
  .subscribe({...});
```

Когда внутренний Observable внутри `concatMap` завершается с ошибкой, ошибка пробрасывается наверх по цепочке. В итоге завершается вся подписка `submit$`, и новые события просто никто не слушает.

Подробнее про оператор можно почитать в [официальной документации catchError](https://rxjs.dev/api/operators/catchError).

## 4. Почини приложение

Твоя задача — обработать ошибку **внутри** внутреннего Observable так, чтобы внешний поток `submit$` продолжал жить и принимать новые значения.

1. Открой `src/app/app.component.ts`.
2. В цепочке операторов найди место, где создаётся запрос `this.http.get(...)`.
3. Добавь оператор `catchError` так, чтобы он обрабатывал ошибку только этого запроса и возвращал какой-нибудь fallback-observable (например, `of(null)`).
4. Убедись, что теперь после ошибочного запроса можно ввести новое значение, нажать **Получить**, и приложение продолжит работать.

Подсказка: `catchError` нужно ставить **внутри** `concatMap`, а не снаружи.

## 5. Проверь решение

Сценарий проверки:

1. Введи `posts` → нажми **Получить** → видишь в ответе JSON.
2. Введи `foo` → нажми **Получить** → видишь в ответе ошибку.
3. Введи `comments` → нажми **Получить** → снова видишь JSON, а не «мёртвый» интерфейс.
4. Повтори шаги 2–3 несколько раз. Каждое нажатие должно по-прежнему логировать значение или ошибку в консоль.

## Ограничения

- Нельзя создавать новые подписки на `submit$` — обработка ошибки должна остаться в рамках одного потока.
- Каждое нажатие кнопки **Получить** должно по-прежнему логировать результат (значение или ошибку) в консоль.
