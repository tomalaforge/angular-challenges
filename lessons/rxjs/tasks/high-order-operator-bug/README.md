# Ошибка в операторе высшего порядка

В этом задании мы найдём и исправим баг, связанный с операторами высшего порядка в RxJS (`merge`, `concat`, `switchMap`, `mergeMap` и т.д.).

## 0. Запуск приложения

Перейди в папку задачи и выполни команду:

```bash
npm install
npm run serve:rxjs-high-order-operator-bug
```

После запуска откроется приложение. На экране — список сущностей (id и тема: `book`, `food`, `sport`) и три кнопки:

- **Delete Food** — удалить все записи с темой `food`
- **Delete Sport** — удалить все записи с темой `sport`
- **Delete Book** — удалить все записи с темой `book`

Удаление идёт через фейковую локальную БД, которая для каждой записи случайно возвращает `true` (успех) или `false` (ошибка).

## 1. Посмотри, что есть

Открой файлы:

- `src/app/app.component.ts` — корневой компонент и кнопка удаления
- `src/app/app.service.ts` — сервис, который собирает удаление нескольких записей в один поток
- `src/app/localDB.service.ts` — фейковая БД

В `app.service.ts` есть метод `deleteOldTopics(type)`, который:

1. Ищет все записи нужного типа через `dbService.searchByType(type)`.
2. Для каждой записи вызывает `dbService.deleteOneTopic(id)`, который возвращает `Observable<boolean>`.
3. Объединяет все эти Observable в один поток.

После нажатия на кнопку `ButtonDeleteComponent` подписывается на результат и показывает сообщение:

- `All <type> have been deleted` — если результат `true`
- `Error: deletion of some <type> failed` — если результат `false`

## 2. Воспроизведи баг

1. Перезагрузи страницу, чтобы восстановить начальные данные.
2. Нажми **Delete Food** несколько раз подряд.
3. В какой-то момент под кнопкой появится сообщение **Error: deletion of some food failed** — значит, в `LocalDBService` хотя бы одна запись вернула `false`.
4. Снова нажми **Delete Food**.

🚫 Снова появится сообщение **All food have been deleted**, хотя мы только что видели ошибку.

Тестировщики говорят, что интерфейс всегда показывает успех, даже если часть удалений не удалась. Это и есть наш баг.

## 3. Найди причину

Открой `src/app/app.service.ts` и посмотри на `deleteOldTopics`:

```ts
return infoByType.length > 0
  ? infoByType
      .map((t) => this.dbService.deleteOneTopic(t.id))
      .reduce((acc, curr) => merge(acc, curr), of(true))
  : of(true);
```

Здесь несколько Observable объединяются через `merge`. Семантика `merge`:

- эмитит значения из всех входных потоков по мере их появления
- завершается, когда завершатся **все** входные потоки
- ошибку пробрасывает наверх, если она случится в любом из потоков

Сейчас же в начальное значение `acc` передаётся `of(true)`. Этот Observable сразу эмитит `true` и завершается. Получается, что подписчик **всегда** видит первое значение `true`, и дальнейшие результаты уже не важны — сообщение об ошибке мы просто игнорируем.

## 4. Почини баг

Нужно сделать так, чтобы финальный результат потока отражал **все** результаты удаления, а не только первый.

Существует несколько подходов. Подумай, какой из них подходит лучше:

- использовать оператор, который «сворачивает» поток в одно финальное значение, например `reduce`/`scan` или комбинацию `combineLatest`/`forkJoin`;
- применить `switchMap`/`mergeMap` к источнику данных и собрать результат уже на уровне сервиса.

Требования к решению:

1. Если **все** удаления вернули `true`, в итоге должно прийти `true`.
2. Если хотя бы одно удаление вернуло `false`, в итоге должно прийти `false`.
3. Внешний интерфейс (`AppComponent`, `ButtonDeleteComponent`) менять не нужно — он остаётся прежним.

Подсказки:

- Помни, что `merge` всегда эмитит каждое значение из входных потоков, а нам нужно «схлопнуть» поток в один boolean.
- Удобно сначала собрать поток `Observable<boolean>` для всех удаляемых записей (например, через `mergeMap`), а потом применить оператор, дающий одно финальное значение.

## 5. Проверь решение

1. Перезагрузи страницу.
2. Нажимай **Delete Food** подряд. Сообщения теперь должны соответствовать реальному результату: если хотя бы одна запись вернёт `false` — должно появиться **Error: deletion of some food failed**.
3. Проверь то же самое для **Delete Sport** и **Delete Book**.
4. Нажми любую кнопку несколько раз, чтобы убедиться, что сценарий воспроизводится стабильно.

## Ограничения

- Нельзя менять поведение `LocalDBService` — фейковая БД специально возвращает ошибки.
- Менять можно только логику в `app.service.ts` (и, при необходимости, архитектуру сервиса), но не публичный интерфейс компонента.
